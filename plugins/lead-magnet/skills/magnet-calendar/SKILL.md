# Magnet Calendar

Read `${CLAUDE_PLUGIN_ROOT}/references/method.md`. One splinter magnet per week is a whole launch runway: every week the list grows, every delivery warms it, and week zero opens doors to a list that already got five wins from you.

## Inputs
The doors-open date (or "evergreen"), the offer, and a splinter board (from splinter-scout, the Build Room, or built here with pick). Need 6 to 8 strong splinters; if fewer, run splinter-scout first.

## Plan
1. **Sequence the splinters** by the buyer's journey toward the offer: early weeks fix awareness-level splinters, later weeks fix splinters whose next step IS the offer. The final magnet's pointer is the waitlist with the real date and seat count.
2. Per week, one row: splinter | magnet name (via name-it rules) | format (vary them - a prompt week, a scorecard week, a teardown week; never the same format twice running) | keyword | posting day | pointer (weeks 1-4 point at reply/newsletter, weeks 5+ point at the waitlist).
3. **The compounding rules**: every delivery email mentions next week's magnet in one line; every post's comments get mined (magnet-loop) so later weeks can swap in hotter splinters; one week is a re-run of the best performer to catch the missed.
4. **The load check**: each magnet is a 90-minute build with build-the-file. Flag any week that is secretly a Vault-sized project and shrink it.
5. Week zero: doors open. The ask email (Day 7 template) goes to the whole runway list; segments from segment-writer if the survey ran.

## Output
The calendar table, the week-one magnet fully specced (ready for /lead-magnet:pack), and the three dates to put in a real calendar today: first post, waitlist pointer switch-on, doors open. Real dates only, counted back from doors-open.
